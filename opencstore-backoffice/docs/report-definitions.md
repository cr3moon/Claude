# Report Definitions

All reports are defined in `src/modules/reports/report-definitions.ts` and generated
via the main-process `ReportService` (`backend/services/ReportService.ts`).

Each report definition specifies:
- `id` — unique string key used in API calls
- `name` — display name shown in the UI
- `description` — short explanation of what the report contains
- `columns` — array of `ReportColumn` objects (key, label, format, align)
- `params` — optional parameter schema (e.g. date range)

Reports are archived to the `reports_archive` table after each run.

---

## Available Reports

### 1. `sales_by_department`
**Sales by Department**

Aggregates total revenue, units sold, and gross margin grouped by department name.
Useful for identifying which categories drive the most profit.

| Column         | Format   | Notes                          |
|----------------|----------|--------------------------------|
| dept_name      | text     | Department name                |
| qty_sold       | integer  | Total units sold               |
| total_revenue  | currency | Sum of price × qty             |
| total_cost     | currency | Sum of cost × qty              |
| gross_margin   | percent  | (revenue − cost) / revenue     |

---

### 2. `sales_by_category`
**Sales by Category**

Like `sales_by_department` but at category level (sub-groups within departments).

---

### 3. `top_items_by_revenue`
**Top Items by Revenue**

Ranked list of PLU items sorted by total revenue descending.
Date range required. Default: last 30 days.

| Column         | Format   |
|----------------|----------|
| pos_plu_id     | text     |
| description    | text     |
| dept_name      | text     |
| qty_sold       | integer  |
| total_revenue  | currency |
| avg_price      | currency |
| gross_margin   | percent  |

---

### 4. `top_items_by_units`
**Top Items by Units Sold**

Ranked by units sold descending. Good for identifying velocity leaders.

---

### 5. `low_margin_items`
**Low Margin Items**

Items where gross margin falls below the department target margin.
Threshold is driven by `DEPT_MARGIN_RULES` in `pricing-rules.ts`.

| Column          | Format   |
|-----------------|----------|
| pos_plu_id      | text     |
| description     | text     |
| dept_name       | text     |
| current_price   | currency |
| current_cost    | currency |
| current_margin  | percent  |
| target_margin   | percent  |
| gap             | percent  |

---

### 6. `price_change_history`
**Price Change History**

All approved and applied price changes, with before/after values.

| Column         | Format   |
|----------------|----------|
| changed_at     | datetime |
| pos_plu_id     | text     |
| description    | text     |
| old_price      | currency |
| new_price      | currency |
| changed_by     | text     |
| source         | text     |

---

### 7. `audit_recommendations`
**Audit Recommendations**

Item data quality flags generated by the normalization rule engine.

| Column      | Format  |
|-------------|---------|
| created_at  | datetime|
| pos_plu_id  | text    |
| description | text    |
| rule_code   | text    |
| severity    | text    |
| suggestion  | text    |
| status      | text    |

---

### 8. `import_job_log`
**Import Job Log**

History of all data import jobs with record counts and status.

| Column           | Format   |
|------------------|----------|
| created_at       | datetime |
| source_type      | text     |
| adapter_type     | text     |
| records_total    | integer  |
| records_ok       | integer  |
| records_skipped  | integer  |
| records_error    | integer  |
| status           | text     |
| triggered_by     | text     |

---

### 9. `shift_summary`
**Shift Summary**

Summary of each recorded shift: cashier, duration, transaction count.

---

### 10. `checklist_completion`
**Checklist Completion**

Rate of shift checklist completion by template and date range.

---

### 11. `backup_history`
**Backup History**

All backup manifest records with size, checksum, and status.

---

### 12. `pricing_recommendations`
**Pricing Recommendations**

All pending, approved, and rejected pricing suggestions.

---

### 13. `department_margin_targets`
**Department Margin Targets**

Reference table of configured margin targets per department pattern.

---

### 14. `inactive_items`
**Inactive / Orphaned Items**

PLU items marked inactive or with no sales activity in the selected period.

---

### 15. `duplicate_upcs`
**Duplicate UPC Report**

Items sharing the same UPC code across different PLU records.

---

### 16. `cost_variance`
**Cost Variance**

Compares current cost against last known cost. Flags items where cost
has increased by more than 5% since the last import.

## Export Formats

| Format | Method              | Notes                                   |
|--------|---------------------|-----------------------------------------|
| CSV    | `exportToCsv()`     | Formatted cells (currency, %, etc.)     |
| CSV    | `exportRawToCsv()`  | Raw numeric values for spreadsheets     |
| Print  | `printReport()`     | Opens browser print dialog              |
| PDF    | `exportToPdf()`     | Stub — TODO: implement with Electron    |

## Adding a New Report

1. Add a `ReportDefinition` entry to `REPORT_DEFINITIONS` in `report-definitions.ts`
2. Add a SQL query `case` in `backend/services/ReportService.ts` `generate()` method
3. The report will automatically appear in the UI dropdown on `ReportsPage.tsx`
